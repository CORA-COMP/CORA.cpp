# Differences from CORA

Where CORA.cpp deliberately differs from CORA's MATLAB code, because CORA's result is wrong or unsound.

| CORA file | What CORA does | What CORA.cpp does | Minimal input |
|---|---|---|---|
| `contSet/@interval/atan2.m` | Returns the hull of `atan2` at the four corners, which misses +-pi across the branch cut | Follows CORALean's guarded definition: the corner hull if `0 < inf x`, `0 < inf y` or `sup y < 0`, else [-pi, pi] rounded outward | `y = [-1, 1]`, `x = [-2, -1]`: CORA gives [-2.678, 2.678] |
| `contSet/@interval/boundaryPoint.m` | For a box unbounded on one side, `Inf*0 = NaN` enters the bound, and `x(inf_dirs) = Inf*sign_dir(d_inf)` uses the wrong mask, so it returns +-Inf | Returns the exit point of the ray; +-Inf only where the ray never leaves (coordinates with `dir = 0` keep `start`) | `I = [0, Inf]`, `dir = -1`, `start = 1`: CORA gives -Inf, the exit point is 0 |
| `contSet/@interval/acosh.m` | The out-of-domain error says the valid domain is '>= -1 && <= 1' | The domain is `>= 1`, as the code checks; the message says so | `acosh(interval(0.5, 2))` |
| `contSet/@interval/enlarge.m` | For a box unbounded on one side and `factor = 1`, `center` is NaN and the bounds become NaN | Keeps the bounds: scaling by 1 is the identity | `I = [0, Inf]`, `factor = 1`: CORA gives `[NaN, NaN]` |
| `contSet/@interval/isIntersecting_.m` | Loops `for i = 1:length(I)` over the linear index, so for an interval matrix only the first max(rows, columns) entries are compared and a disjoint later entry is missed | Compares every entry | `I = interval(zeros(2), ones(2))`, `S = interval([0 5; 0 5], [1 6; 1 6])`: CORA gives true |
| `contSet/@zonotope/lift_.m` | Projects onto `proj` (`project(Z, proj)`), which is the inverse permutation of what `lift` documents (state `i` goes to position `proj(i)`); the two agree only where `proj` is its own inverse | Puts state `i` at position `dims[i]`, as `lift` of intervals and polytopes does | `Z = zonotope([1;2;3])`, `proj = [2 3 1]`: CORA gives (2;3;1), CORA.cpp (3;1;2) |
| `contSet/@zonotope/encloseMany.m` | Reduces each set with `reduce(Z, 'parallelpiped')`, a method `reduce` does not have, so it fails with `CORA:wrongValue` | Reduces to order 1 (Girard), as CORALean's definition does | `encloseMany({zonotope([0;0], eye(2))}, [1;0])` |
| `contSet/@zonotope/enclosePoints.m` | `'maiga'`: when the compression vector `g` vanishes (all points equal, or the first singular vector orthogonal to the box radius), `u = g / norm(g)` is `0/0` and the points become NaN | Skips the compression, so the cloud is unchanged and still enclosed | `enclosePoints([1 1 1; 2 2 2])` |
| `contSet/@zonotope/isIntersecting_.m` | For points, calls `contains_(Z, S, type, tol, false, false)` with six arguments where `contains_` takes seven, and fails | Answers with `contains` of all points, up to `tol` | `isIntersecting(zonotope([0;0], eye(2)), [0;0])` |
| `contSet/@zonotope/norm_.m` | `'exact'` maximizes `\|G u\|` over `u in {-1,1}^m` and returns the norm of `c + G u`, which is not the maximum norm for `c ~= 0` | Refuses `'exact'` (it needs a mixed-integer solver) | `Z = zonotope([10; 0], [1 0; 0 1])`: the maximizer ignores `c` |
